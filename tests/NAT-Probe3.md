# 3차 진단: 위치와 뒤쪽 필드 개수 분리

두 파일은 진단 전용이며 운영 목록에 합치면 안 됩니다. 기존 운영 파일은 변경하지 않았습니다.

1. `NAT-Probe3-Position.ini`와 `NAT-Probe3-Suffix.ini`를 SecureCRT 설정 폴더의 Keywords에 복사합니다.
2. 현재 세션의 색상 강조 및 구문/부분 문자열 매칭을 유지합니다.
3. 목록을 `NAT-Probe3-Position`으로 선택하고 `do sh ip nat t`의 새 출력 화면을 기록합니다.
4. 목록을 `NAT-Probe3-Suffix`로 바꾸고 같은 명령의 새 출력 화면을 기록합니다.
5. 두 화면에 각각 Position/Suffix 표시를 붙여 전달합니다. 장비 설정 변경은 필요 없습니다.

두 목록 모두 Pro=빨강, icmp=분홍, ---=은색입니다. 주소:식별자의 기대 색은
왼쪽부터 골드, 시안, 하늘색, 보라입니다. 이 대조 항목이 안 보이면 목록 선택부터 확인합니다.

Position은 행 시작에서 고정 문자 수만큼 떨어진 위치를 lookbehind로 검사합니다.
NAT 행 형식이나 남은 필드 개수는 검사하지 않습니다. 사진에서 확인한 주소 시작
offset 4/5, 23/27, 42, 56/61만 지원하므로 다른 배치는 기본색으로 남거나 오색칠될 수 있습니다.
주소 경계의 단순 검사는 부분 숫자 매칭을 줄이기 위해 유지합니다.

Suffix는 뒤에 남은 endpoint 또는 --- 개수만 lookahead로 검사합니다.
lookbehind나 행 시작 검사는 없습니다. 따라서 다른 명령의 줄 끝 IP도 색칠할 수 있으며,
누락된 필드가 있으면 열 역할이 잘못 표시될 수 있습니다. 운영용으로 사용하지 마세요.

| Position 주소색 | Suffix 주소색 | 다음 판단 |
| --- | --- | --- |
| 성공 | 성공 | 두 조건 단독은 작동. 이전 중첩 조합을 더 작게 분리해 확인 |
| 실패 | 성공 | 뒤쪽 문맥 기반 매칭 후보 확보. 행 시작 참조/위치 조건 문제는 미확정 |
| 성공 | 실패 | 위치 참조는 작동. 뒤쪽 필드 검사/행 끝 처리 추가 확인 |
| 실패 | 실패 | 단순 lookbehind 성공을 주소 규칙에 일반화할 수 없음. 더 작은 주소 대조군 필요 |

검증 명령: `pwsh -NoProfile -File tests/NatProbe3.Tests.ps1`
자동 검사는 .NET의 전체 행 문맥 보존 모델이며 SecureCRT 렌더링을 증명하지 않습니다.
어느 결과든 모든 NAT 배치나 운영 목록과의 우선순위 호환성이 확인되는 것은 아닙니다.
