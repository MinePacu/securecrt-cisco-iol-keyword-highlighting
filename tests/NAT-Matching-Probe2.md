# NAT 2차 화면 검증

상태: 자동 검사는 가능하지만 SecureCRT 실제 렌더링은 사용자 화면 확인 대기 중입니다.

## 1차 관찰

사용자가 제공한 NAT-Matching-Probe 화면에서 일반 문자열, 여러 단어, lookahead,
고정 길이 lookbehind, endpoint 내부의 부분 문자열 강조는 성공했습니다.
동일 화면의 anchored-prefix `\K`와 `DEFINE`/이름 있는 서브패턴 규칙은 색상이
나타나지 않았습니다. 이것만으로 앱 전체의 문법 지원 여부나 길이 제한을 단정하지 않습니다.

## 이번에 분리해서 확인할 항목

- 행 시작 기준 고정 길이 lookbehind 내부에 lookahead를 넣어 NAT 행인지 검사할 수 있는가?
- 이미 앞쪽 열이 강조된 상태에서도 그 문맥을 읽을 수 있는가?
- 남은 endpoint 개수로 열 역할을 확인하면서 IP와 포트/ICMP 식별자 전체를 강조하는가?
- 정적 NAT의 첫 두 주소와 빈 필드도 정상 표시되는가?

14개 규칙으로 구성했으며 각 패턴은 최대 240자입니다. `\K`, `DEFINE`, 서브패턴 호출은
없습니다. 256자는 진단 파일의 자체 제한일 뿐 SecureCRT의 공식 제한이라는 뜻은 아닙니다.

## 적용 방법

1. NAT-Matching-Probe2.ini를 SecureCRT 설정 폴더의 Keywords 폴더에 복사합니다.
2. 현재 세션의 키워드 목록을 NAT-Matching-Probe2로 선택합니다.
   색상 강조와 구문/부분 문자열 매칭을 유지합니다.
3. 기존 `do sh ip nat t` 명령으로 새 출력을 표시합니다. 장비 설정은 변경하지 않습니다.
4. 제목과 ICMP 행, 정적 NAT 행이 보이게 화면을 보내 주세요.

| 항목 | 기대 색상 |
| --- | --- |
| Pro | 빨강: 이 진단 목록이 선택되었다는 대조 표시 |
| tcp/udp/icmp | 분홍 |
| Inside global 제목 및 주소:식별자 | 골드 |
| Inside local 제목 및 주소:식별자 | 시안 |
| Outside local 제목 및 주소:식별자 | 하늘색 |
| Outside global 제목 및 주소:식별자 | 보라 |
| --- | 은색 |

## 범위와 해석

이 파일은 운영용이 아닙니다. 제공된 화면의 배치에 맞춰 주소 시작 offset(0 기준)을
Inside global=4/5, Inside local=23/27, Outside local=42, Outside global=56/61로
한정했습니다. 더 짧거나 긴 주소/식별자, 다른 공백 배치에서는 일부 주소가 기본색으로
남을 수 있습니다. 주소의 값 자체를 하드코딩하지 않았고, 남은 열 개수도 함께 검사합니다.

- 제목/프로토콜만 색칠되면 새로 시험하는 주소 문맥 조건이 아직 성공하지 않은 것입니다.
- 한 열만 실패하면 해당 주소 시작 위치와 남은 필드 형식부터 확인합니다.
- 네 주소 열 전체가 맞으면 이 한정된 배치에서의 복합 매칭이 입증됩니다.
  이를 모든 NAT 출력이나 기존 운영 목록과의 우선순위 호환성으로 확대 해석하지 않습니다.

자동 테스트: `pwsh -NoProfile -File tests/NatProbe2.Tests.ps1`
Git/PCRE 문법 검사와 전체 행 문맥을 유지하는 .NET 후보 위치 스캔을 사용합니다.
두 검사 모두 SecureCRT 자체의 테스트가 아닙니다.
